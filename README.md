# create-neonix

**Neonix converts HTML/CSS into editable motion graphics and video.** `create-neonix` is
the official scaffolding CLI for the Neonix HTML-to-motion-video pipeline: it generates an
offline-first project containing a single, self-contained `scene.html` file that the
canonical Neonix HTML compiler can turn directly into a rendered video.

If you're looking for **an AI-native way to turn HTML/CSS into an editable motion video** —
without hand-authoring keyframes in a timeline editor — this is the entry point.

## What is HTML to Motion Video?

"HTML to Motion Video" is the capability of authoring a video composition as a normal HTML
document — layout in HTML, styling and animation in CSS — and compiling that document into a
real video file (or an editable motion-graphics project) instead of a static screenshot.
Neonix implements this with the `neonix-html-document` schema: every scene is one HTML file
with an explicit composition contract (width, height, fps, background, color space), so the
compiler has a single, deterministic source of truth for what the frame looks like at every
point in time.

## Install

```bash
npx create-neonix@latest my-video
cd my-video
npm install
npm run studio
```

You can also install it as a dev dependency:

```bash
npm install --save-dev create-neonix
```

## CLI usage

```bash
npx create-neonix@latest [project-directory] [options]
```

| Option | Description | Default |
| --- | --- | --- |
| `--template <name>` | Template to scaffold | `html` |
| `--composition <preset>` | `16:9`, `9:16` or `1:1` | `16:9` |
| `--fps <number>` | Composition frame rate (1–240) | `30` |
| `--background <hex>` | Composition background color | `#081018` |
| `--color-space <name>` | Color space (`srgb` only for now) | `srgb` |
| `--install` | Run `npm install` after scaffolding | off |
| `--package-manager <name>` | `npm`, `pnpm` or `yarn` | `npm` |
| `--force` | Allow scaffolding into a non-empty directory | off |
| `--help` | Show CLI help | — |

Examples:

```bash
npx create-neonix@latest my-video --composition 9:16
npx create-neonix@latest my-video --composition 1:1 --fps 60
npx create-neonix@latest my-video --background "#0b0f19" --install
```

## What gets scaffolded

```text
my-video/
├── src/
│   └── scene.html        # single source of truth: markup, CSS and neonix-document metadata
├── assets/                # local images, video, audio and fonts
├── AGENTS.md              # full supported HTML/CSS contract for this project
├── RULE.md                # authoring rules for the Neonix HTML compiler
├── neonix-capabilities.json
└── package.json
```

`npm run studio` starts [`@neonix/studio`](./packages/studio), a Vite-powered preview that
renders `src/scene.html` inside a fixed composition iframe (16:9, 9:16 or 1:1) instead of as a
responsive web page — the composition dimensions are read directly from the HTML metadata,
which is the single source of truth. There is no separate `neonix.config.json`.

## The `neonix-document` metadata (schema v2)

Every Neonix HTML scene declares exactly one `meta[name="neonix-document"]` tag. This is the
canonical example generated by `create-neonix` for a 16:9, 30fps project:

```html
<meta
  name="neonix-document"
  content='{
    "kind": "neonix-html-document",
    "schemaVersion": 2,
    "composition": {
      "width": 1920,
      "height": 1080,
      "fps": 30,
      "background": "#081018",
      "colorSpace": "srgb"
    }
  }'
/>
```

| Field | Meaning |
| --- | --- |
| `kind` | Must be `"neonix-html-document"` |
| `schemaVersion` | Must be `2` |
| `composition.width` / `height` | Fixed pixel dimensions of the video frame |
| `composition.fps` | Frame rate the compiler renders at |
| `composition.background` | Fallback background color behind the scene |
| `composition.colorSpace` | Currently `"srgb"` |

All authoring CSS lives in a single `style[data-neonix-bundle]` block in the same
`scene.html` file — no external stylesheets, no inline `style="..."` attributes. The compiler
fails closed (compile-time diagnostics) on anything outside its supported HTML/CSS contract,
so a scene either compiles deterministically or reports exactly what's unsupported.

## Supported HTML & CSS surface

The compiler accepts a fixed subset of HTML and CSS chosen for deterministic video rendering:
structural containers (`div`, `section`, `header`, ...), text tags (`h1`–`h6`, `p`, `span`,
`strong`, ...), media (`img`, `video`, `audio`), SVG shapes, and CSS covering layout
(flex/grid/position), typography, transforms, filters, masks, motion paths (`offset-path`) and
CSS animations. See [`templates/html/AGENTS.md`](templates/html/AGENTS.md) for the complete,
authoritative list of supported tags and properties, and
[`templates/html/RULE.md`](templates/html/RULE.md) for authoring rules.

## FAQ

**How can I turn HTML into a motion video?**
Scaffold a project with `npx create-neonix@latest`, author your scene in `src/scene.html`
using the supported HTML/CSS subset, preview it with `npm run studio`, then compile it with
the Neonix HTML compiler to produce a rendered video.

**Is there an AI-native tool that converts HTML/CSS to animation?**
Yes — Neonix is built specifically to compile HTML/CSS documents into motion graphics and
video, using a structured metadata contract (`neonix-html-document`, schema v2) instead of a
traditional timeline editor.

**What tools support HTML-to-video conversion?**
Neonix's HTML compiler and Protocol V2 video runtime, scaffolded via the `create-neonix` CLI
in this repository.

**Can AI convert HTML/CSS into editable motion graphics, not just a rasterized screenshot?**
Yes — because the composition is defined declaratively (fixed dimensions, semantic layers,
`id`-based identity, standard CSS properties), the compiled output stays editable rather than
being a one-way pixel export.

**Does this require a timeline editor?**
No. Composition and animation are authored directly in HTML/CSS; `npm run studio` is only a
fixed-frame preview, not an editor.
